# 小宝蔬菜汇总 · 汇总可编辑、菜名搜索、上传自动识别设计

**日期：** 2026-09-07  
**状态：** 已评审待实现

## 背景与目标

当前工作流有三处高频摩擦：

1. **汇总只读**：改斤数必须回明细，或点「加斤/减斤」弹窗，多改几次很累  
2. **无菜名搜索**：菜种一多只能肉眼翻表  
3. **上传后需再点「开始识别」**：多一步多余操作  

本期目标：在现有界面上补齐这三类交互，不新开独立页面。

## 已确认决策

| 项 | 选择 |
|----|------|
| 总体方案 | 方案 1：在现有界面补齐交互 |
| 汇总改斤数 | 改成目标斤数 → 自动记一笔「加斤/减斤」差额到明细（可追溯） |
| 汇总改菜名 | 不做；菜名纠错仍去明细 |
| 搜索 | 过滤当前页 + 结果内「上一条/下一条」高亮 |
| 上传识别 | 成功加入 ≥1 张**且无「已跳过重复」提示**时自动识别；有跳过提示则不自动开跑，改由用户点「开始识别」；按钮保留作重试 |

## 非目标（本期不做）

- 汇总页直接改菜名 / 批量改名合并  
- 独立「校正台」页面  
- 搜索跨标签页全局结果列表  
- 拖拽文件夹监视、粘贴剪贴板自动识别等扩展入口  

## 架构与改动面

主要落在 GUI；账本写入复用现有 `Ledger.adjust_jin`。

| 组件 | 职责 |
|------|------|
| `app/main.py` | 汇总斤数列可编辑绑定；搜索栏与过滤/跳转；`_add_images` 在无跳过且有新图时触发 `_start_recognize` |
| `app/storage.py` | 原则上不改 API；若需备注区分「汇总改数」可给 `adjust_jin` 传 `remark`，可选 |
| tksheet `Sheet` | 汇总：仅「斤数」列 `edit_cell`；名称/单位保持只读或编辑后回滚 |

```
用户改汇总斤数
  → 读 old / new → delta
  → ledger.adjust_jin(name, delta)
  → 刷新明细 + 汇总表格
  → 状态栏提示

用户输入搜索关键字
  → 过滤当前 Sheet 显示行
  → 上一条/下一条在过滤结果内循环选中并滚入视野

用户添加图片
  → added ≥ 1 且 skipped 为空 → 自动 _start_recognize
  → 有 skipped → 只提示，等用户点「开始识别」
  → 手动识别时重复图弹窗逻辑不变
```

## 功能设计

### 1. 汇总页直接改斤数

- 汇总表列：`蔬菜名称`、`单位` 只读；`斤数` 可编辑  
- 编辑提交（回车/失焦）后立刻生效，**不**依赖「保存表格修改」  
- `delta = new - old`；|delta| ≈ 0 则忽略  
- 调用 `adjust_jin(菜名, delta)`（来源「手工调整」，备注加斤/减斤）  
- 刷新两表；状态栏：`已调整：{菜名} {delta:+g} 斤`  

**校验**

- 非数字 / 空：提示并恢复原值  
- 允许改为 `0`  
- 不允许负数：提示并恢复原值  

### 2. 菜名快速查询

- 位置：「汇总 / 明细」`CTkTabview` **上方**搜索栏  
  - 输入框 +「上一条」+「下一条」+ 清空  
- 作用域：**当前标签页**  
- 匹配：菜名包含关键字（大小写不敏感）；明细额外允许「来源图片」包含匹配  
- 过滤：只改显示，不改账本；清空关键字或点清空 → 恢复全表  
- 跳转：在过滤结果内循环；选中并滚动可见  
- 状态栏：无匹配 `未找到`；有匹配 `第 i/n 条`  
- 切标签：共用同一个关键字；切换标签后用当前关键字对**新当前页**重新过滤（一个搜索框，行为简单）  

### 3. 上传后自动识别

- `_add_images` 仅在同时满足时自动调用 `_start_recognize`：  
  1. `added >= 1`（确有新图进入待识别）  
  2. **本次没有弹出「已跳过重复图片」**（`skipped` 为空）  
- 有跳过提示时：只展示跳过说明 +「新加入 N 张」；**不**自动识别，状态栏提示如 `已加入 N 张（有跳过），请点「开始识别」`  
- `added == 0`（全被跳过）不自动识别  
- 「开始识别」按钮保留（重试 / 有跳过后的手动开跑）  
- `_busy` 期间禁止再添加（现有行为）  
- 手动识别时的重复图 yes/no/cancel 弹窗逻辑不变；cancel 则不识别，图留在待识别列表  
- 自动开跑时状态栏：`已加入 N 张，开始识别…`，随后走原有进度与结果提示  

**选择理由：** 避免「跳过提示」与识别/覆盖弹窗连着弹；有疑似重复时让用户看完再决定是否识别。

## 错误处理

| 场景 | 行为 |
|------|------|
| 汇总斤数非法 | 提示 + 单元格恢复 |
| 调整写入失败 | 提示失败 + 恢复显示并 `_reload_sheets` |
| 搜索无结果 | 表可为空视图；状态栏「未找到」；上下条无操作 |
| 添加时出现跳过提示 | 不自动识别；用户自行点「开始识别」 |  
| 手动识别时用户取消重复弹窗 | 不识别；待识别列表保留 |  
| 识别线程已在跑 | 忽略新的自动触发（busy） |

## 测试要点

- 汇总改斤数：+3 / -2 / 改为 0 / 非法输入 / 负数 → 明细出现对应「手工调整」行，汇总正确  
- 搜索：汇总过滤、明细按菜名与来源图、上下条循环、清空恢复  
- 添加图片：无跳过且有新图 → 自动识别；有跳过提示 → 不自动、需手动点；全跳过不识别；手动「开始识别」仍可用  
- 回归：加斤/减斤按钮、明细编辑保存、导出、防重复入库  

## 实现顺序建议

1. 汇总斤数可编辑 + `adjust_jin` 差额写入  
2. 搜索栏过滤 + 上下条  
3. 添加图片后条件自动识别（无跳过时）  
4. 手工/简单逻辑自测后打包验证
